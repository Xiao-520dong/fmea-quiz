📖 今日核心知识

1. 核心概念与定义
  • FMEA-MSR 失效分析目的（4.4.1 节）：在相关操作场景下，说明导致最终影响的完整事件链（失效起因 → 监视 → 系统响应 → 减轻的失效影响）。通过参数图或失效网建立产品失效链，作为表格记录和风险分析的基础，并促进客户与供应商之间的协作。
  • 失效场景定义（4.4.2 节）：由特定操作条件与事件序列组成的系统状态演进过程。起点为确定的失效起因，终点为最终的失效影响。分析核心聚焦于具有诊断能力的组件（ECU/MCU）。
  • 故障处理时间间隔（Fault Handling Time Interval, FHTI）：在安全机制未激活或失效的前提下，从故障发生到危险事件或不合规失效影响产生之间的最大允许时间跨度。
2. 方法步骤与三大失效场景对比拆解
根据系统是否具备诊断能力及安全机制响应，手册将失效场景划分为三种典型路径：
  • 场景 (1) —— 无危险事件（S = 1~9，无安全机制或未触发）：故障出现 → 产生故障行为（失效模式） → 经过一定时间演变为最终影响。此影响不会造成人身危险，但可能导致功能丧失、客户抱怨或法规不合规（如通信丢失、显示异常）。
  • 场景 (2) —— 危险事件（S = 10，安全机制未激活/不存在）：故障出现 → 发生故障行为 → 超过故障处理时间间隔（FHTI） → 直接引发危害人身安全的危险事件（如电池热失控、电机失控夹伤）。在此场景中，FHTI 评估是安全设计的硬约束。
  • 场景 (3) —— 减轻/减缓影响（含监视与系统响应）：故障出现 → 发生故障行为 → 在 FHTI 内完成故障探测与系统响应（系统响应时间 = 探测时间 + 过渡时间 ≤ FHTI） → 系统进入安全状态或降级模式 → 避免危险事件，最终影响仅为功能的损失或退化（严重度降低，M 评价生效）。
3. 传音研发/制造实战场景（以智能手机 68W 超快充热保护为例）
在传音中高端机型快充架构中，PMIC/电荷泵具备硬件与固件联合监视能力：
  • 失效起因（FC）：主板 USB 接口 NTC 热敏电阻焊点受跌落应力虚焊，输出异常悬空高阻抗信号。
  • 无系统响应场景（场景 2 风险）：若充电管理芯片未设计开路检测与超时机制，大电流持续灌入，电芯温度突破极限引发起火/热失控（S = 10 危险事件），该过程跨越的时间即为系统热击穿时间窗口。
  • 有系统响应场景（场景 3 缓解）：系统定义 FHTI 为 1.5 秒。PMIC 内部看门狗与 ADC 诊断机制在 200ms 内探测到 NTC 阻值突变（探测时间），并在 300ms 内强行拉低 PWM 驱动、断开快充路径并回退至 5V/500mA 安全供电（过渡时间）。系统总响应时间 500ms < 1.5s，成功将危险降级为“弹出充电异常提示，仅维持慢充”（S 降低，功能降级但无危险）。
4. 常见误区与避坑指南
  • 误区一：混淆 DFMEA 探测度与 MSR 监视响应：工程师常将产线 EOL 测试或研发测试当作 MSR 响应。纠正：FMEA-MSR 的失效分析完全立足于“终端客户使用过程中的在线实时诊断与响应”，非制造/测试端手段。
  • 误区二：忽略“系统响应时间 ≤ 故障处理时间间隔”这一前提：以为只要写了“系统切入保护”就必然能减轻严重度。纠正：如果软件滤波或硬件关断过渡时间超过了物理破坏的 FHTI 窗口，危险事件依然会先一步爆发，降级逻辑无效。
  • 误区三：认为场景 (3) 可以消除所有失效影响：纠正：场景 (3) 的结果是“减缓的失效影响”，通常伴随功能的退化、降级或安全停机，必须如实记录降级后的影响并评估严重度。
